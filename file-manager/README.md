# File Manager

Консольное приложение для навигации по локальной файловой системе и выполнения файловых команд. Разбор команд отделён от их исполнения и от вывода результатов.

## Возможности

- Подключение к каталогу и навигация по дереву.
- Просмотр дерева с указанной глубиной и содержимого текстового файла.
- Команды перемещения, переименования, удаления и копирования; ограничения реализации перечислены ниже.
- Последовательная обработка строк стандартного ввода до EOF.

## Устройство

`Lab4.Core` содержит команды `ICommand`, контроллер подключения и абстракцию `IFileSystem`. `LocalFileSystem` реализует локальные операции. `Lab4.Presentation` связывает цепочки разбора команд и аргументов с builders команд. Для дерева применены компоненты файловой системы и visitor; вывод отделён через `IWriter`.

Это демонстрирует Command, Chain of Responsibility, Builder и Visitor на конкретной задаче. Реализована только локальная файловая система, несмотря на наличие абстракций расширения.

## Сборка и тестирование

Нужен .NET SDK 9.0.306 или более новый patch в той же feature band, допускаемый `global.json`. При первом восстановлении необходим доступ к NuGet. Команды выполняются из корня репозитория.

```sh
dotnet restore file-manager.slnx
dotnet build file-manager.slnx -c Release --no-restore
dotnet test file-manager.slnx -c Release --no-build
```

GitHub Actions повторяет эти команды для `main` и pull requests. Рабочие процессы подготовлены локально; запуск на GitHub не выполнялся.

## Запуск

```sh
dotnet run --project src/Lab4.Presentation/Lab4.Presentation.csproj -c Release --no-build
```

Введите команды по одной строке. Для завершения подайте EOF: Ctrl+D в macOS/Linux. Отдельной команды `exit` нет. Пути в командах используют `/`; абсолютный путь после подключения отсчитывается от подключённого каталога, а не от корня компьютера. `connect` принимает настоящий абсолютный путь ОС.

## Команды

| Команда | Назначение |
|---|---|
| `connect /path/to/directory -m local` | Подключить каталог |
| `disconnect` | Отключиться |
| `tree goto docs` | Перейти относительно текущего каталога |
| `tree goto /docs` | Перейти относительно точки подключения |
| `tree list -d 2` | Показать дерево глубиной 2 |
| `file show notes.txt -m console` | Показать текст |
| `file move notes.txt /archive/notes.txt` | Переместить в указанный полный путь файла |
| `file rename notes.txt draft.txt` | Переименовать |
| `file delete draft.txt` | Удалить |
| `file copy source.txt destination.txt` | Команда присутствует, но имеет дефект; см. ниже |

Для воспроизводимой демонстрации в macOS/Linux:

```sh
bash scripts/demo.sh
```

Скрипт создаёт собственный временный каталог, показывает дерево и текст, переименовывает, перемещает и удаляет демонстрационный файл. В выводе дважды появляется `Hello from File Manager!` и подтверждения выполнения команд. После завершения временный каталог удаляется.

## Ограничения сохранённой реализации

- `file copy` требует существования файла назначения, а затем вызывает `File.Copy` без перезаписи и с исходными, не нормализованными аргументами. Обычный сценарий копирования не работает корректно.
- `file move` принимает путь конечного файла; описанное в условии назначение как каталога не реализовано автоматически.
- Проверка нахождения внутри подключённого каталога использует строковый префикс. Это не надёжная изоляция файловой системы. Новое имя в `file rename` также не ограничено одним именем без пути.
- Ошибки ввода-вывода и коллизии имён могут завершить приложение исключением. Содержимое файла читается целиком.
- Демонстрация использует простые пути без пробелов и только собственные временные файлы. Приложение не следует использовать как защищённую файловую песочницу.
